# 潜在指纹增强 —— 基于多尺度 PatchGAN 的条件生成对抗网络

> **山东省大学生数学建模竞赛 三等奖** ｜ D 题「潜在指纹增强问题」

山东省大学生数学建模竞赛 D 题「潜在指纹增强问题」的建模与求解代码。

## 一、问题背景

潜指纹（latent fingerprint）是案发现场提取的指纹检材，与现场采集的活体指纹不同，
它普遍存在**脊线结构模糊、背景噪声强、有效面积小**等问题，直接导致后续的特征点
（minutiae）提取与比对失败。

本题要求设计算法，在**放大脊线结构对比度**的同时**抑制背景噪声**，把低质量的
潜指纹增强为接近标准采集质量的图像，从而提升指纹识别系统的比对准确率。

## 二、方法

整体思路是把「潜指纹 → 增强指纹」当作一个**成对的图像到图像翻译**任务，
用条件生成对抗网络（conditional GAN）学习该映射。低层用 L1 损失约束像素级保真，
高层用对抗损失约束脊线纹理的真实感。

```
                           ┌──────────── L1 损失 (λ=5) ────────────┐
                           │                                      ▼
模糊潜指纹 ──► 生成器 G ──► 增强指纹 ──┐                    真实清晰指纹
   (512×512)   (U-Net)      │          │
                            │          └──► 判别器 D ──► 真/假
                            └──────────────────────────────┘
```

### 2.1 生成器：带跳跃连接的 U-Net

| 部分 | 结构 |
|---|---|
| 编码器 | 7 个下采样块，`Conv2d(4×4, stride=2, pad=1)` + `BatchNorm2d` + `LeakyReLU(0.2)`，通道 1→64→128→256→512→512→512→512 |
| 解码器 | 7 个上采样块，`ConvTranspose2d(4×4, stride=2, pad=1)` + `BatchNorm2d` + `ReLU` |
| 跳跃连接 | 每个解码层与同尺度的编码层在通道维**拼接**（concat），把编码阶段保留的边缘/脊线细节直接送到解码阶段 |
| 输出层 | `Conv2d(3×3)` + `Tanh`，映射回单通道 512×512 |

第一层编码刻意不加 BatchNorm，避免在输入单通道灰度图上归一化掉原始强度信息。
跳跃连接是这类任务的关键：纯编解码结构在 7 层下采样后空间细节损失严重，
脊线的连续性会断裂。

### 2.2 判别器：多尺度 PatchGAN

判别器接收**通道拼接的图像对** `[模糊图, 待判定图]`（2 通道），
因此它评判的是「这张增强图与该模糊输入是否匹配」，而非孤立地评判单张图像。

单一尺度的判别器容易只关注局部纹理而忽略全局脊线走向，因此这里用了
**3 个尺度**：主干之外，用 `AvgPool2d(3, 2, 1)` 连续下采样得到 1/2、1/4 分辨率的输入，
三个子判别器结构相同、各自独立：

```
Conv2d(2→64, 4×4, s2) → LeakyReLU(0.2)
Conv2d(64→128, 4×4, s2) → LeakyReLU(0.2)
Conv2d(128→256, 4×4, s2) → LeakyReLU(0.2)
Conv2d(256→512, 4×4, s2) → LeakyReLU(0.2)
Conv2d(512→1, 4×4, s1) → AdaptiveAvgPool2d(1)
```

所有卷积层都加了**谱归一化**（spectral normalization）约束 Lipschitz 常数，
抑制判别器训练过程中的梯度爆炸与模式崩溃。

### 2.3 损失函数与热身阶段

**生成器损失**（对抗损失取三个尺度之和）：

```
L_G = Σ_k BCEWithLogits(D_k(fake), 1)  +  λ · L1(G(blur), sharp)      λ = 5
```

**判别器损失**（三个尺度取平均）：

```
L_D = (1/3) Σ_k [ BCEWithLogits(D_k(real), 1) + BCEWithLogits(D_k(fake), 0) ]
```

训练前 **2 个 epoch 为热身期**：判别器冻结，生成器只用 `λ·L1` 损失优化。
这样做是因为训练初期生成器输出接近随机噪声，若立刻引入对抗损失，
判别器会迅速取得压倒性优势并给出无信息的梯度，导致生成器无法收敛。

**优化器**：Adam，生成器 `lr=2e-4`、判别器 `lr=1e-4`，`betas=(0.5, 0.999)`；
配合 `StepLR(step_size=30, gamma=0.5)` 每 30 轮学习率减半。

### 2.4 数据与训练配置

- 输入尺寸 512×512 单通道灰度，归一化到 `[-1, 1]`
- 数据增强：以 0.5 概率随机施加 ±10° 旋转与水平翻转
- 批大小 4，训练 100 轮
- 每轮保存一张「输入 / 生成 / 真值」三联对比图到 `training_samples/`，
  并保存当轮生成器权重到 `saved_models/`

## 三、运行

### 环境

```bash
pip install -r requirements.txt
```

### 训练

`--blur-dir` 与 `--sharp-dir` 下需存放**文件名一一对应**的图像对：

```bash
python src/enhance.py \
    --blur-dir  /path/to/blur \
    --sharp-dir /path/to/sharp \
    --epochs    100 \
    --batch-size 4 \
    --out       final_generator.pth
```

### 输出

| 路径 | 内容 |
|---|---|
| `final_generator.pth` | 最终生成器权重 |
| `saved_models/generator_epoch_N.pth` | 每轮生成器权重 |
| `training_samples/epoch_N.png` | 每轮三联对比图 |
| `results/` | 测试集增强结果 |

## 四、结果

`results/` 下为测试集增强输出，命名规则 `enhanced_<样本号>_<序号>.png`，
共 15 个样本 × 8 张。

## 五、实验过程代码

`src/enhance.py` 是最终提交的算法。但建模不是一步到位的 —— 从拿到检材到定下
cGAN 方案，中间走了一整条实验链路，这些都保留在 `experiments/` 下
（**20 个脚本，约 2700 行**）：

| 阶段 | 目录 | 做什么 |
| --- | --- | --- |
| ① 图像检查 | `lab_0/判断是否灰度图.py` | 先确认检材的通道与灰度分布，避免后续处理踩错格式 |
| ② 匹配评分 | `lab_1/指纹匹配评分.py` | 调用匹配工具对「检材 vs 库指纹」逐对比对，拿到原始分数 |
| ③ 效果评估 | `lab_2/ROC_AUC评估.py` | 用比对分数画 **ROC 曲线并算 AUC**，建立可量化的评价基准 |
| ④ 生成式增强 | `lab_3_gan/` | GAN 路线的早期实验，含输入尺寸标定的辅助脚本 |
| ⑤ 预处理与指标 | `lab_4/` | **FFT 去除周期性噪声**、数据集封装、评价指标 |
| ⑥ 模糊增强模型 | `lab_6/` | 后续的模糊处理与模型实现（416 行） |
| ⑦ 质量指标工具 | `质量指标工具/` | 自实现指纹图像质量指标：**脊线宽度 BRW、方向场 DM、局部质量 QM、LFM、Min**，以及一套指纹匹配实现 |

这条链路本身就是这个项目最值得说的部分：**先建立可量化的评价基准（ROC/AUC），
再迭代增强方案**，而不是直接上模型看效果。`质量指标工具/` 里那几个指标
（BRW / DM / QM 等）是通用的指纹质量评价量，自实现一遍是为了能针对本题的
检材特点调整阈值。
